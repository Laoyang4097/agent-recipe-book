# 「解题经验共享库 · Agent 可浏览」方向深度调研

> 调研时间：2026-09-23｜目标：评估"把用 AI 解题的曲折过程（含死胡同）分享成网站、让 Agent 能直接浏览调用"这个方向能否拿「卓越杯」B 赛道

## 一句话结论

**方向成立，且比前几个方向更"拿奖相"。** 你这个点子正好踩在 2026 年 AI 工程界最热的一条赛道上——**Agent 共享经验记忆 / 群体经验学习（Shared Agentic Memory / Fleet Memory）**。但你的切角（**人类贡献"含死胡同的解题过程"，校园向、机器可读、人机共用**）目前市面上**没有对应产品**，是一片干净的空白。

⚠️ **唯一要守住的诚实底线**：不能说"全球首创共享记忆"（Spark、Caura、AWS 都已做），必须精确说成"**首个面向校园/人类贡献、专门捕获'解题过程与死胡同'、且机器可读的经验库**"。

---

## 一、这个方向在现实里对应什么（不是空想）

### 1. 学术前沿：Spark（Memco，arXiv 2511.08301，2025-11）
- 论文标题 *"Smarter Together: Creating Agentic Communities of Practice through Shared Experiential Learning"*。
- 核心：让 AI 编程智能体**既贡献、也读取**一个持久的"经验记忆"，模拟人类开发者社区的集体智慧。
- 实测：借 Spark，一个 30B 小模型代码质量**追平**了大得多的大模型；推荐"有用性"最高两档达 **98.2%**。
- 关键词正是 **"Communities of Practice（实践社群）"**——这跟管理学院的"知识管理/组织学习"理论直接对上，评委秒懂。
- *来源质量*：arXiv 预印本，学术可信；98.2% 为论文自报指标。

### 2. 产品现状（都在做"共享记忆"，但都是给**代码智能体**用的）
| 项目 | 形态 | 与你方向的差异 |
|---|---|---|
| **Caura** | 开源(Apache-2.0)、MCP 原生"智能体舰队记忆" | 给自主代码 Agent 写 runbook，**不是人类贡献** |
| **AWS Bedrock AgentCore Memory** | 跨终端/跨人"团队记忆"服务层 | 企业级、闭源托管 |
| **Armalo Memory Mesh** | 多智能体共享记忆底座 | 强调密码学可验证，偏底层基础设施 |
| **Sajal Sharma 共享知识库** | AGENTS.md + skills + 每日笔记的个人"共享大脑" | 个人多 Agent 协同，非众包 |
| **GBrain**（Garry Tan） | Agent 记忆层，已开源 | 个人记忆，非经验库 |
| **skills-mcp / Agent Skills Directory** | 语义可搜的"技能注册表"，JSON 机器可读 | 是"怎么做"，不是"踩了什么坑" |

### 3. **你的"死胡同"洞察，正是这个领域的核心价值点**
- Memco 原话：共享记忆能"**把失败成本降低 34%，因为它让 Agent 不再去探索已知的死胡同（known dead ends）**"。
- Caura：舰队记忆"**由 Agent 自己写**，用治理机制代替人类策展"。
- → 你直觉到的"兜兜绕绕才解决"恰好是这个领域的金矿。**差异只在：你要把"人类踩坑过程"变成结构化、可机读、可众包的资产**，而不是只让代码 Agent 自己写。

## 二、"Agent 能浏览这个网站"——有真实标准，不是 PPT 概念

你设想的"所有 Agent 可以浏览"，对应的真实工程标准是 **`llms.txt`** 和 **MCP / 机器可读端点**：

- **`llms.txt`**（Jeremy Howard / Answer.AI 提出，2024-09；v2 于 2026-08）：放在网站根目录的 Markdown 文件，给 LLM 一份"精选内容地图"，一次抓取替代盲目爬 HTML。配套 `llms-full.txt` 一次返回全文。
- **真实先例**：`mcp-codex.com` 明确写"任何自主 Agent 爬取本域都拿到**纯结构化知识、无 HTML 噪声**"；`Agent Skills Directory` 是自动更新的 JSON 目录，被 MCP server 直接消费；`skills-mcp` 用语义向量 + 三级渐进披露让 Agent 按需取用。
- **这对你意味着**：网站除了给人看，再挂一个 `llms.txt` / 公开 JSON / 简易 MCP，就真的能"让别的 Agent 来读你的经验库"——这是你区别于普通博客/知乎"踩坑帖"的**技术护城河**，也是答辩时的"哇点"。

⚠️ **诚实 caveat（别在报告里吹过头）**：`llms.txt` 目前** adoption 仅约 10%**，Google 的 John Mueller（2025-06）直言"目前没有 AI 系统真正读取 llms.txt"，30 万域名研究也显示**无 citation 提升**。结论：它是"面向未来的基础设施"，比赛里作为**架构亮点**完全成立，但别宣称"搜索引擎会因此多引你"。评委是人，这点不影响打分。

## 三、为什么这个方向对「卓越杯 B 赛道 + 管理学院评委」特别合适

1. **B 赛道要"可运行 Demo"** → 网站（投稿表单 + 经验列表）+ 一个演示 Agent 来查它，完美契合。
2. **"AI+X"主题** → 知识管理 × AI，正中。
3. **理论钩子拉满（管理学院评委最爱）**：
   - **SECI 模型 / 知识管理**（Nonaka）：隐性知识（踩坑过程）→ 显性化（结构化经验库）→ 再内化。
   - **实践社群 / 组织学习**（Wenger、Spark 论文直接用这词）。
   - **集体智慧 / 复利效应**：一条踩坑经验被 N 个 Agent/同学复用 = 边际成本趋零。
4. **差异化极强，避开同质化**：现有校园 AI（清小搭、山小芽、小叶、职悟空）**全是"问答机器人"**；你这是"**集体记忆/经验资产平台**"，结构层面就不一样，评委一眼能看出区别。
5. **"海底捞式超预期"落点实**：正常服务只给你"答案"；你给"**别人踩过的坑、你不用再踩**"——这正是"你没想到但我替你想到了"的惊喜感，且比"陪伴舱"实在、Demo 里看得见。

## 四、16 天低代码 MVP 架构（可交付、不膨胀）

**只保两条线，防 scope creep：**
- 线 A：**人类贡献的经验库**（核心）
- 线 B：**机器可读接口**（llms.txt / JSON，让 Agent 能读）——这是"哇点"担当

| 层 | 低代码做法 | 说明 |
|---|---|---|
| 投稿 | 飞书多维表格 / 表单 | 字段：问题、试过但失败的(死胡同)、最终解法、用的工具、领域标签、贡献者(可匿名) |
| 展示 | 静态站(MkDocs/Notion 页) 或 Coze 知识库 | 列表 + 搜索 + 标签筛选 |
| Agent 可读 | 自动生成 `llms.txt` + 公开 JSON | 每次新投稿重写，Agent 一次抓取即得全库摘要 |
| 演示 Agent | Coze 搭"经验向导" | 学生说"我被XX卡住了"→ 检索经验库 → 返回"别人怎么破局+别踩哪些坑" |
| 治理(亮点) | 贡献者署名 + 有效性投票 + 审核 | 呼应 Memco 的"信任分级"，显你专业、负责任 |

**Demo 记忆点**：学生输入"用 RAG 搭知识库一直报错"→ 暨南经验库回：① 3 条学长真实踩坑（切片大小/嵌入模型中文适配/版本回退）②"你没问的：暨南隐藏福利/相关讲座"。**"你没问的，我先给你了"** = 海底捞超预期，但落在扎实资源上。

## 五、风险与红线（评委/校方必挑刺，先想好）

1. **别误称"首创共享记忆"**：Spark/Caura/AWS 都做了。精准表述="首个校园/人类贡献/过程捕获版"。
2. **经验质量治理**：错误经验会传播。MVP 用"审核 + 署名 + 投票 + 标注'经验有效性'"，反而成"负责任 AI"亮点。
3. **隐私**：贡献者身份、敏感问题细节 → 匿名化、脱敏。
4. **llms.txt 诚实定位**：作为架构亮点，不吹 SEO/citation。
5. **冷启动**：经验库初期条目少。对策：你作为就业办可先导入 10–20 条真实"暨南学长踩坑案例"（脱敏），并拉同学众包投稿。

## 六、与之前几个方向的定位对比

| 方向 | 状态 | 本方向相对优势 |
|---|---|---|
| 就业版海底捞（陪伴舱） | 已证伪（Demo 显不出差异化、易雷同） | 本方向 Demo 可见、结构差异化强 |
| 暨安·就业安检员（反诈） | 稳但偏工具 | 本方向更具"让人眼前一亮"的惊喜感 |
| 暨囊·集合全校资源 | 盘子大易膨胀 | 本方向是"资源"的**高价值子集**（人的经验），更聚焦 |
| 暨南惊喜盲盒 | 不错但偏轻 | 本方向理论厚度+技术护城河更利于拿奖 |

**建议定位**：把"解题经验共享库"作为主项目，("集合全校资源"可降级为它的一个内容维度——经验本身就是最值钱的资源)。
