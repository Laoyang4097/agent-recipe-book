# 「解题配方库 · Agent 可浏览」开源策略与开放边界决策

> 背景：在"解题经验共享库"方向上进一步细化——不只记录"答案"，而是记录**完整解题配方**：用了什么模型（Hy3 / Deepseek-V4.1-flash 等）、用了什么 skill、harness / soul / Agent.md 长啥样、电脑什么配置；统一脱敏后，做成**开源 + 全站 Agent 可读 + 支持 MCP/CLI** 的经验资产。本文回答五个决策问题：要不要开源？要不要 MCP/CLI？开放多少边界？怎么组织成 Agent 易读？

---

## 一句话结论

**开源，且必须开源**（概念本身要求"让所有 Agent 浏览"，闭源自相矛盾）；**MCP/CLI 先不做**（用 `llms.txt` + 公开 JSON 即可满足"Agent 可读"，自研 MCP server 是工期炸弹）；**开放边界 = 配方全开、敏感信息全脱敏**（模型/技能/harness/soul/Agent.md/硬件规格全公开，真名/学号/密钥/内网 URL/绝对路径一律清洗）。

---

## 决策一：要不要做成开源？—— 要，且这是概念的前提

**核心矛盾**：你想"让所有 Agent 浏览这个网站找到解决方法" + "又怕被复制粘贴"。**这两件事在逻辑上冲突**——Agent 要读得了，就必须是公开可抓取的；你越想防抄，越违背产品初衷。

**但"怕被抄"的担心其实是搞反了，证据如下：**

1. **赛事层面，开源是加分项甚至硬性要求**：MoonBit 全球编程挑战赛明确要求入围决赛队伍"以 OSI 认可的开源协议之一公开发布源代码"；RoboMaster 组委会长期"倡导技术开源、营造分享氛围"。评审普遍把开源视为 maturity signal。
2. **你的真正护城河不是代码，是三样抄不走的东西**：① 就业办**官方公信力**（学生敢托付真实数据）；② **人工策展 + 真人兜底权**（商业产品无此权限）；③ **实时/校本数据**（scdc 登录态、侨校/多校区专属）。代码被 fork 不影响这三点。
3. **开源反而防抄**：配 `LICENSE` + 署名水印 + 贡献者致谢榜，别人用了你的数据/配方必须注明出处（参照 RoboMaster 保护说明）。白嫖者反而在学术诚信上被动。
4. **"被抄去参赛"风险极低**：卓越杯是校级赛，且你占据"就业办官方首发 + 时间先发"位置，后来者反而要解释"为何与你的开源库高度相似"。

**协议选择**：
- 求最大传播/零负担 → **MIT**（个人/学生项目首选，CS  starter guide 明确推荐）。
- 想防"拿了你的开源还反告你专利"、或未来接企业合作 → **Apache 2.0**（含 explicit patent grant + NOTICE 机制）。
- 本项目建议 **MIT**（传播优先，配置库不是专利敏感资产）。

## 决策二：要不要支持 MCP？—— MVP 不做，作为 Phase 2

**关键区分（决定你少走弯路）**：
- 你想做的是"**Agent 来读你的经验库**" → 这是 **读取知识**，用 `llms.txt` / `llms-full.txt` / 公开 JSON 即可，**不需要 MCP**。
- MCP 解决的是"**Agent 调用你的工具/执行动作**"（如让 Agent 往你库里写一条、或触发某个操作）——这是你 Phase 2 才需要的"写入/交互"能力。

**自研 MCP server 的真实成本（多源一致）**：
- Silent Infotech / SolGuruz / WorldProgramming 三源一致：一个最小**只读** MCP server（5–10 工具 + OAuth + 审计）也要"数周"、外部报价 $20K–$150K；带写操作翻倍；且协议仍在演进（2026-07 有 breaking change），需**持续维护**。
- ContextBolt 直说："2026 年大多数人不需要自建 MCP server，80% 情况装现成的就够了。"
- 对 16 天低代码学生 MVP，**自建 MCP = 工期炸弹**，且你当前没有"会写后端的队友"假设。

**结论**：MVP 用 `llms.txt` + JSON 实现"全站 Agent 可读"（30 分钟部署，零成本）；**MCP 列为决赛后 Phase 2 升级项**，且仅在有技术队友时做"只读 MCP server"（让别的 Agent 用标准协议查你库）。

---

## 决策三：要不要支持 CLI？—— 轻量只读即可，重 CLI 放 Phase 2

- MVP 只需保证"Agent 和人类都能读"：提供 `curl https://yoursite.com/llms-full.txt` 或 `curl https://yoursite.com/api/experiences.json` 即可，这本身就是最朴素的"CLI 友好"。
- 完整 CLI 工具（安装包、子命令、鉴权）属 Phase 2，优先级低于内容积累。**不要为 CLI 单独投入 MVP 工期。**

---

## 决策四：应该开放多少边界？—— 配方全开，PII 全脱敏

你想记录的字段，按"该不该公开"分三层：

| 字段 | 是否公开 | 说明 |
|---|---|---|
| **使用的模型**（Hy3 / Deepseek-V4.1-flash 等） | ✅ 公开 | 核心可复现信息，正是别人最想要的 |
| **使用的 skill 列表** | ✅ 公开 | 同理，价值点 |
| **harness / 运行框架** | ✅ 公开 | 结构信息，非敏感 |
| **soul / Agent.md（系统提示/人格）** | ✅ 公开（脱敏后） | 这是"配方"精华；只删掉其中的真名、学号、内网路径 |
| **电脑配置**（CPU/RAM/GPU/OS/内存） | ✅ 公开 | **硬件规格不是敏感信息**，恰恰是"可复现性"关键，鼓励全留 |
| 真实姓名 / 学号 | ❌ 脱敏 | 改"某同学/匿名"或贡献者昵称 |
| API Key / Token / 内部 URL | ❌ 严禁 | 任何密钥、内网地址、带权限的链接一律删 |
| 文件系统绝对路径（如 `C:\Users\ZhuanZ1\...`） | ❌ 脱敏 | 改相对路径或占位符 |
| 聊天记录原文含他人隐私 | ❌ 脱敏 | 只留"问题-失败-解法"结构 |

**脱敏原则（来自 AI Agent Secrets Management 研究）**：密钥/PII 绝不以明文进模型上下文、日志、检索索引；入库前统一 redact；配置类内容（Agent.md/soul）本身不是秘密，是可贡献资产，只洗掉嵌在其中的个人标识。

**建议流程**：每条投稿 → 飞书多维表/表单收集 → **自动 + 人工二次清洗**（正则匹配 key/学号/路径 + 人工复核）→ 生成脱敏后的 markdown + JSON。

## 决策五：怎么组织成 Agent 易读？—— 套用开放标准，三件套交付

**关键洞察**：你描述的"harness / soul / Agent.md"恰好对应业界刚统一的 **Agent Skills 开放标准（SKILL.md）**——Anthropic 2025-12-18 发布为开放标准，已被 OpenAI、Google Gemini CLI、Cursor、GitHub Copilot 等 30+ 产品采用（无需 SDK，纯 Markdown + YAML）。**把你每条"解题配方"写成 SKILL.md 兼容格式，等于自动接入整个 Agent 生态**，这是巨大的"哇点"和"Agent 可读"加分项。

### 交付三件套（MVP 即可做）

1. **`/llms.txt`**（根目录，30 分钟）：站点索引，按意图分组链接到各配方 markdown，每条带一句话价值描述（参照 DigBI / tools.town 最佳实践：5–20 条优先页、绝对 URL、<20KB、Claude 会主动抓取）。
2. **`/llms-full.txt` 或 `/api/experiences.json`**：全量配方正文（纯 Markdown / JSON），Agent 一次抓取即得全库——这就是你说的"整个网站支持 Agent 阅读"。
3. **每条配方一个 `.md` 文件（SKILL.md 兼容结构）**，字段如下：

```yaml
---
name: 解决XX问题的配方
description: 当遇到[问题特征]时，用此配方复现解法
model: Hy3            # 使用的模型
skills: [skill-a, skill-b]   # 使用的 skill
harness: WorkBuddy   # 编排框架
domain: [就业, 编程, 校园]
contributor: 匿名同学A   # 已脱敏
license: MIT
---
# Soul / Agent.md（脱敏后的人格与系统提示要点）
<此处放清洗后的人格设定>

# 环境与配置（硬件规格，全公开）
- CPU: i5-10210U
- RAM: 8GB
- GPU: 集成 UHD
- OS: Win10

# 问题
<原始问题>

# 试过但失败的（死胡同，核心价值）
- 尝试A：为什么不行
- 尝试B：卡在哪

# 最终解法
<可复现步骤>

# 复盘
<为什么这次成了 / 踩坑提醒>
```

### Agent 读取闭环示意
> 别的学生/别的 Agent 遇到同类问题 → 抓 `llms-full.txt` 或调 `/api/experiences.json` → 检索到这条配方 → 直接复现"模型+技能+配置+解法"，**绕开你当初兜兜绕绕的死胡同**。这正好把你最初"AI 解题不稳定、常绕弯路"的痛点，转化成"集体经验资产"。

## 对比赛（卓越杯 B 赛道）的契合度

- **可运行 Demo**：网站（投稿表单 + 配方列表 + `/llms.txt`）+ 一个 Coze「经验向导」演示 Agent 来查它 → 完美契合"可演示 AI 原型"。
- **差异化空白（已多轮验证）**：清小搭/山小芽/小叶全是"问答机器人"；Spark/Caura 是"代码 Agent runbook"；**你是"人类贡献 + 机器可读 + 含死胡同 + 校本"的配方库，结构层面就不同**。
- **管理学院理论钩子**：SECI 知识管理模型（隐性踩坑→显性化→再内化）、实践社群（Wenger，Spark 论文原词）、集体智慧复利、可复现性（Reproducibility）。
- **诚实边界（答辩必说）**：不称"全球首创共享记忆"（Spark/Caura 已存在），精准表述为"**首个校园/人类贡献/专门捕获解题过程与死胡同/机器可读的开源配方库**"。

## 16 天 MVP 排期（只保两条线防膨胀）
- Day1–3：飞书多维表 + 投稿表单 + 脱敏流程
- Day4–8：网站（列表 + 详情 + `/llms.txt` + `/api/experiences.json`）
- Day9–11：Coze「经验向导」演示 Agent（查库返回"别人怎么破局+别踩哪些坑"）
- Day12–14：攒 ≥10 条真实配方（发动就业办/校友/同学投稿）
- Day15–16：录屏 + 说明书 + 路演 PPT
- **Phase 2（决赛后）**：只读 MCP server、完整 CLI、贡献者致谢榜上链

## 红线提醒
- 开源 ≠ 放弃署名：根目录 `LICENSE`（MIT）+ 数据水印"本配方库由暨南大学就业办首发"。
- 投稿前**强制脱敏**：正则 + 人工双审，密钥/学号/内网 URL/绝对路径一律清除。
- `llms.txt` 别吹"提升搜索排名"（Google 2026-05 明确说不是排名因素），它是"面向未来的架构亮点"，比赛够用，别夸大。
- 若接 scdc 真实数据，注意 tzgg/xngs 可能含姓名学号，必须脱敏后再入库。

## 与前面方向的收敛关系
建议把"解题配方库（开源 + Agent 可读）"**作为主项目**；之前讨论的"集合全校资源（暨囊）"降级为它的**内容维度之一**——人/作品/情报本身就是全校最值钱的"资源配方"。这样方向不发散、MVP 收敛、且概念最锋利。
