**项目本质定义**：用就业办内部视角，做一个**具体、可演示、有校本级数据护城河**的AI就业辅助原型，在2分钟demo里让评委感到"这跟别家不一样且真有用"。

**成功标准（暂定）**：Demo能在一句话内说清"谁+什么麻烦+我怎么解决"；有≥10个真实暨南学生试用反馈；功能≤1个主workflow。

**约束**：零/低代码优先、16天、不得依赖需审核的小程序。

## 步骤2：第一性原理拆解（习惯 vs 核心事实）

**【核心事实·不可动摇】**
1. 评委只认"具体场景+真实落地+差异化"，不认宏大概念（多源评委视角一致）。
2. 就业办身份 = 真实学生用户 + 校本级数据 + 公信力，这是商业公司和别校抄不走的。
3. 16天只够一个单点MVP（2周MVP铁律：一个输入-一个AI处理-一个输出）。
4. 比赛Demo是2分钟路演，必须"一眼看懂爽点"。

**【习惯·可砍掉】**
- ✂️ "海底捞"营销比喻（太消费化、边界模糊，评委难映射到business value）。
- ✂️ 多功能堆叠（被拒急救+隐藏雷达+求职战报+预判关怀+真人兜底 = scope creep爆雷）。
- ✂️ 抓官网scdc全栏目（登录墙+无RSS，技术风险高，非比赛必需）。
- ✂️ 微信主动推送/SaaS化（决赛后才做，非初赛必交）。

## 步骤4：诺伊曼反向死因（方案A致命死因）

| 死因 | 可控性 | 规避 |
|---|---|---|
| 评委觉得"又是个聊天机器人，和浙大小叶没区别" | 中 | Demo脚本专门设计"被拒急救"对比：普通bot回"继续加油" vs 暨小捞给具体行动，制造反差爽点 |
| 知识库没真内容，答非所问 | 高 | 用你手头真实暨南就业案例/FAQ做知识库，3天填完 |
| 被拒案例涉及隐私 | 高 | 全匿名化+脱敏，demo用合成案例 |
| "情感"在文本里显得假/尬 | 中 | Prompt设定"克制共情、重行动"，避免鸡汤，评委（商科）更吃"可执行" |

## 步骤10：金字塔汇报（一页纸+PPT大纲）

**一句话**：做一个"被拒后第一时间急救"的暨南专属AI就业助手，用真实校本级数据和真实学生试用，打出"别人只改简历、我们捞人"的差异化。

**PPT大纲（5分钟路演）**：
1. 痛点：暨南学生被拒后无人管、"继续加油"式反馈无效（真实问卷/案例）
2. 方案：暨小捞·被拒急救室——一次对话给共情+3步行动+校资源
3. 差异化：对比普通就业bot的"继续加油" vs 我们的"具体捞法"
4. 落地：≥10真实学生试用反馈 + 迭代记录（证据链）
5. 价值：就业办可真部署、校本级数据护城河、可扩展抓取层

**核心话术**："市面上的就业AI都在帮你'投'，我们在你'被拒'时接住你——这是正常就业服务绝对没有的。"
